# مجلس المحللين — نشر مستمر وحفظ دائم

تطبيق عربي لمتابعة بيانات BTC/USDT، عرض اتجاهات المحللين، الشارت ودفتر الأوامر، وقياس نتائج النموذج تاريخياً. لا ينفّذ أوامر تداول ولا يضمن التنبؤ بحركة الشمعة التالية.

## النشر على Dokploy (موصى به)

1. أنشئ خدمة **Compose** داخل المشروع.
2. اربط مستودع Git الذي يحتوي مجلد `main`.
3. اجعل **Compose Path**:
   `./main/docker-compose.yml`
4. في **Environment** يمكنك إضافة `AUTH=username:password` للمصادقة. لا تعتمد عليها كحماية آمنة إلا عندما يكون الاتصال عبر HTTPS.
5. في **Domains** اختر خدمة Compose `council`، واترك Path وInternal Path على `/`، واجعل **Container Port = 8080**.
6. احفظ الإعدادات واضغط **Deploy**.

**ملاحظة HTTPS:** نطاق `sslip.io` قد يظهر في Dokploy كخدمة HTTP فقط ولا يصدر له SSL. عند استخدامه افتح الموقع عبر `http://` للتجربة فقط، ولا تدخل كلمات مرور أو بيانات حساسة. لحماية تسجيل الدخول فعلياً، استخدم نطاقاً تملكه مع شهادة HTTPS صالحة.

لا تضف `ports: 80:80` ولا توجّه الدومين إلى المنفذ 80. التطبيق يستمع داخل الحاوية على `8080`، وDokploy/Traefik يتولى توجيه الدومين.

## حفظ البيانات بعد Redeploy

- ملف الحالة الدائم: `/data/state.json`.
- نسخة الاستعادة السابقة: `/data/state.json.bak`.
- Docker Compose يركّب Volume صريح الاسم `council-data` على `/data`.
- الحفظ الذري يتم بعد تغيّر سجل التعلّم أو التوقع المقفل، مع حفظ دوري احتياطي، وليس اعتماداً على ذاكرة المتصفح.
- إعادة نشر الحاوية مع إبقاء Volume `council-data` لا تمسح سجلّ التعلّم.
- **لا تحذف Volume `council-data` ولا تستخدم أمر حذف الـ volumes** عند إعادة النشر.
- لتنزيل نسخة احتياطية يدوياً افتح `/api/backup` من نفس الدومين بعد تسجيل الدخول. حالة التخزين متاحة عبر `/api/storage`.

إذا حذفت الخدمة أو الـ Volume بالخطأ، فلن يستطيع التطبيق استعادة السجل من تلقاء نفسه؛ احتفظ بنسخة من `council-backup.json` في مكان آمن.

## تخزين سحابي دائم عبر Supabase (موصى به)

الحفظ في Volume يكفي عادة، لكنه يضيع إذا حُذفت الخدمة أو الـ Volume أو نُقل الخادم. Supabase نسخة سحابية ثانية تنجو من كل ذلك.

1. أنشئ مشروعاً مجانياً في supabase.com.
2. افتح **SQL Editor** ثم **New query**، والصق محتوى ملف `supabase.sql` واضغط **Run**.
3. من **Project Settings ثم API** انسخ **Project URL** ومفتاح **service_role** (وليس anon).
4. في Dokploy، قسم **Environment**، أضف:

```text
SUPABASE_URL=https://xxxxxxxx.supabase.co
SUPABASE_SERVICE_KEY=مفتاح_service_role
```

5. اضغط **Deploy**. في Logs يجب أن ترى `supabase: connected` أو `supabase: restored state from the cloud copy`.

كيف يعمل:

- عند كل إقلاع يقارن الخادم النسخة المحلية بالسحابية ويستعيد الأحدث تلقائياً، فلا تفقد التعلّم عند Redeploy.
- يرفع الحالة كل 60 ثانية إذا تغيّرت (`SUPABASE_PUSH_SECONDS` لتغيير المدة، والحد الأدنى 15)، وعند إيقاف الحاوية.
- يحفظ نسخة يومية باسم `daily-YYYY-MM-DD` ويحتفظ بآخر 14 يوماً.
- تحقق من الحالة عبر `/api/storage`، حقل `supabase`.
- مفتاح `service_role` سري: ضعه في Environment فقط، ولا تضعه في الكود أو في الواجهة.
- يعمل الحفظ في Volume بالتوازي، فإن تعطلت Supabase يستمر الحفظ المحلي.

## إعداد الخدمة محلياً

```bash
cd main
docker compose up -d --build
```

بدون Docker (Node.js 22+):

```bash
AUTH='viewer:كلمة_مرور_قوية' DATA_DIR=./data PORT=8080 node server.js
```

المتغيرات:

- `AUTH`: اختياري، بصيغة `username:password`.
- `PORT`: الافتراضي `8080`.
- `DATA_DIR`: الافتراضي `/data` داخل الحاوية.

## التحقق بعد النشر

من لوحة Dokploy افتح **Logs**. من الطبيعي أن ترى:

```text
started 1m
started 3m
started 5m
started 15m
started 1h
started 4h
listening on 8080
```

تحقق أيضاً من:

- `http://YOUR-HOST/healthz` — يجب أن يعيد `ok` (استخدم `https://` فقط إذا كان TLS مضبوطاً فعلاً).
- `http://YOUR-HOST/api/storage` — يجب أن يعرض `ok: true` واسم إطار أو أكثر بعد بدء المحرك.
- `http://YOUR-HOST/api/backup` — ينزّل ملف JSON احتياطياً (يتطلب المصادقة عند تفعيل `AUTH`).

## بيانات Binance

المحرك يتصل بواجهات Binance العامة للشموع، التداولات وعمق السوق. اختبر اتصال الخادم من الـ VPS:

```bash
curl -s https://api.binance.com/api/v3/time
```

يجب أن يرجع JSON يحتوي `serverTime`. إذا رجع رفض موقع أو تعذّر الاتصال، فمصدر المشكلة هو إتاحة Binance من موقع الخادم أو الشبكة، وليس الواجهة.

## تفسير الأرقام

- «جودة النموذج» درجة مركبة لاتفاق المدارس وقوتها؛ **ليست احتمال نجاح**.
- لا تُعرض نسبة نجاح محافظة إلا بعد توفر 100 نتيجة تاريخية مماثلة على الأقل. وتظل النسبة تقديراً إحصائياً لا ضماناً.
- دفتر الأوامر لقطة لطلبات معلّقة قابلة للإلغاء، وليس سجلاً للصفقات المنفذة.
- الاختبار الرجعي منفصل عن الأداء الحي ولا يضمن استمرار النتيجة نفسها.
